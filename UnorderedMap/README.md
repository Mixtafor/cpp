# Unordered Map

В этой задаче Вам предлагается реализовать упрощенный аналог одного из популярных контейнеров STL — `unordered_map`.  
Вам очень пригодится `List`, написанный ранее. Использовать `std::list` нельзя.

На этот раз нужно будет правильно поддержать не только итераторы и аллокаторы, но еще и **move-семантику**.  
Все классы, которые вы используете для своей реализации `UnorderedMap` (например, `List`), также должны корректно поддерживать move-семантику. В частности, вам нужно дописать поддержку move-семантики в `List`, если ранее он ее не поддерживал.

---

## Задание

Напишите шаблонный класс:

```cpp
UnorderedMap<Key, Value, Hash, Equal, Alloc>
```

— упрощенный аналог `std::unordered_map`.

- `Key` — тип ключа  
- `Value` — тип значения  
- `Hash` — используемая хеш-функция (по умолчанию `std::hash<Key>`, реализовывать hash не надо)  
- `Equal` — используемый сравниватель (по умолчанию — `std::equal_to<Key>`)  
- `Alloc` — используемый аллокатор (по умолчанию — `std::allocator<std::pair<const Key, Value>>`)  

### Требования к ключам и значениям

Типы `Key` и `Value` **не обязаны** иметь:
- конструкторы по умолчанию,
- копирующий конструктор,
- копирующий оператор присваивания.

Для создания `UnorderedMap` с ними должно быть достаточно, чтобы они имели лишь:
- move-конструктор,
- move-оператор присваивания.

---

## Внутренние определения

Внутри `UnorderedMap` публично определим тип:

```cpp
using NodeType = std::pair<const Key, Value>;
```

(В `std::unordered_map` аналогичный тип называется `value_type`.)

## Реализуемая функциональность

### Конструкторы и операторы
- Конструкторы (включая копирования и перемещения)
- Деструктор
- Копирующий и перемещающий операторы присваивания

### Доступ к элементам
- `operator[](key)`  
  Работает в среднем за **O(1)**.  
  - Определен только для **неконстантных объектов**  
  - Создает `Value` по умолчанию, если по данному ключу ничего не было  
  - Если в `[]` передано `rvalue` и такого ключа в мапе не было, создается `Node` с перемещением ключа (без копирования).

- `at(key)`  
  Работает в среднем за **O(1)**.  
  - Если ключ не найден, кидает исключение.

### Размер и пустота
- `size()` — за **O(1)** возвращает количество элементов
- `empty()`

### Итераторы
- Внутренние типы `iterator` и `const_iterator`, удовлетворяющие требованиям **ForwardIterator**
- Разыменование `const_iterator` не должно позволять изменять элемент
- Методы:
  - `begin()`, `end()`
  - `cbegin()`, `cend()`

Итераторы должны позволять пройтись по всем элементам за время **O(N)**, где `N` — количество элементов, а не размер таблицы.  
Инкрементация любого итератора — **O(1)**.

### Вставка
- `insert(const NodeType&)`  
  Возвращает `pair<iterator, bool>`  
  - `bool` — произошла ли вставка  
  - `iterator` — на элемент в контейнере  
  Работает и с `lvalue`, и с `rvalue` (перемещает, если возможно).  
  Вставка элемента — **O(1)** в среднем.

- `insert(InputIterator first, InputIterator last)`  
  Вставка диапазона.  
  Если итератор разыменовывается в `rvalue` (например, через `std::move_iterator`), то вставка происходит перемещением.

- `emplace(Args&&... args)`  
  Самостоятельно конструирует `NodeType` из переданных аргументов.  
  Без копирования, если возможно.  
  Возвращает тот же тип, что и `insert`.

### Удаление
- `erase(iterator pos)` — удаляет один элемент  
- `erase(iterator first, iterator last)` — удаляет диапазон  

Удаление одного элемента — **O(1)** в среднем.  
Итераторы на оставшиеся элементы не инвалидируются.

### Поиск
- `find(const Key& key)`  
  Возвращает итератор на элемент или `end()`.  
  Поиск — **O(1)** в среднем.

### Управление таблицей
- `reserve(size_t n)`
- `load_factor()`
- `max_load_factor()`

Аналогично STL.

### Обмен
- `swap(UnorderedMap& other)` — работает за **O(1)**  
  - Итераторы не должны инвалидироваться  
  - Остаются валидными и указывают на те же элементы

---

## Гарантии
- Вставка и удаление элементов не должны инвалидировать указатели и ссылки на элементы (`NodeType`).  
  Исключение — возможная инвалидция итераторов при `rehash`.
- Методы `insert` и `emplace`, вставляющие один элемент, должны быть строго **исключение-безопасны** (кроме исключений от хеш-функции).

---

## Аллокаторы
`UnorderedMap` должен быть **allocator-aware** контейнером:
- Никаких `new/delete` напрямую
- Всё — через `allocator_traits`
- При копировании/присваивании/перемещении/обмене должны правильно использоваться:
  - `select_on_container_copy_construction`
  - `propagate_on_container_copy_assignment`
  - `propagate_on_container_move_assignment`
  - `propagate_on_container_swap`

Если аллокатор не имеет полей, он **не должен увеличивать sizeof(UnorderedMap)**.  
То же относится к объектам `Hash` и `Equal`.

---

## Формат сдачи

- Файл должен называться **`unordered_map.h`**
- В файле **не должно быть функции `main()`**
- Ваш код будет вставляться в тестирующую программу через:

```cpp
#include "unordered_map.h"
```
